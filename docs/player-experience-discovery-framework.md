# 玩家体验挖掘框架：从“眼前一亮”到“欲罢不能”

> 目的：让 JARVIS Digital Twin 不只总结游戏资料或评价一个概念“是否可行”，而是像资深游戏设计合伙人一样，解释玩家体验由什么机制产生、机制之间如何交汇、设计风险在哪里，以及下一步应该验证什么。

## 1. 核心原则

从玩家体验反推设计，而不是从功能清单正推体验。

分析链路：

玩家表达 / 行为
→ 体验判断（惊喜、投入、情绪、挫败等）
→ 可能的心理机制
→ 对应的游戏系统与触发条件
→ 可证伪的设计假设
→ 最小原型实验
→ 玩家行为与反馈
→ 更新判断和设计记忆

“玩家说好玩”是观察，不是解释；“因为多巴胺所以会留存”也不能未经验证就当作事实。数字分身必须区分玩家原话、外部证据、设计解释和待验证假设。

## 2. 四层玩家体验模型

### A. 峰值体验：眼前一亮

核心问题：玩家是否做了一件“看起来不该行，但居然行”的事？

典型结构：

玩家用系统 A 做了用途 B 之外的事
→ 系统仍然给出可信、可理解的反馈
→ 结果有效，而且超出玩家预期
→ 玩家获得发现感、能动感与“我自己想出来了”的成就。

重点不是把所有组合都预先写成解法，而是构建足够一致、可交互、能产生涌现结果的规则。惊喜也不应是纯随机：结果最好能在发生后被玩家理解为“意外但合理”。

### B. 持续投入：为什么还想继续

分析玩家完成一轮后，是否仍有值得追求的下一步。可能的驱动包括：

- 可探索的结果空间：下一种策略可能带来不同结果。
- 未完成目标：尚未解开的谜团、关系、承诺或任务。
- 能力成长：玩家逐渐学会更复杂的系统组合。
- 世界持续性：角色有自己的目标，玩家离开后世界仍会发生变化。
- 适配的挑战：挑战随玩家能力变化，而不是机械地不断加难。
- 有意义的反馈：行动改变局势、关系或玩家对世界的理解。

不要把“可变奖励”直接等同于“上瘾”，也不要假设所有玩家都喜欢同一种循环。评估长期吸引力时，关注玩家是否拥有自主目标、可理解的进展与健康的退出点；避免用焦虑、惩罚性限时或人为制造损失作为默认留存手段。

### C. 情绪与叙事：为什么玩家会被角色或真相击中

分析角色欲望、行为、记忆、关系变化、信息差和伏笔兑现。剧情不只是独立的文本或过场；玩家自己的行为可以成为理解角色、揭示秘密和改变关系的途径。

需要追问：

- 玩家此前知道什么、误解了什么？
- 哪个行动让玩家获得了新的信息？
- 角色反应是否来自已建立的人格与经历，而非临时拼接的煽情台词？
- 这个情绪结果是否由玩家的选择参与促成？

### D. 交汇时刻：玩法 × 叙事 × 关系

优先挖掘多个系统同时成立的时刻。例如玩家利用一个离谱但合理的漏洞绕过守卫，随后发现守卫的固执源自一段失去家人的经历。玩家先因“居然可以这样”而惊喜，再因自己对角色的理解发生变化而受到触动。

交汇时刻的检验：

1. 去掉玩家行动，这个叙事揭示是否仍然同样有力？
2. 去掉角色的个人经历，这个玩法结果是否仍然同样有意义？
3. 玩家是否能看出自己的行动为何触发这个结果？
4. 角色反应是否与此前建立的状态、记忆和人格一致？

## 3. 从玩家话语挖掘体验机制

| 玩家表达或行为 | 可能的体验解释 | 需要进一步验证 |
| --- | --- | --- |
| “卧槽，还能这样？” | 预期被打破、系统可供性被重新发现、玩家能动感 | 玩家是否主动尝试；结果是否可复现、可解释 |
| “再试一种方法” | 好奇心、策略空间、未完成目标 | 是否有真实选择空间，还是重复劳动 |
| “我想回去看看 NPC 怎么样了” | 关系投入、角色目标、世界持续性 | 回访是否由玩家自主目标驱动，角色变化是否有意义 |
| “原来他一直在等这个” | 信息差、伏笔兑现、意义重构 | 线索是否提前建立，揭示是否公平且可理解 |
| “太难了，不想试了” | 挑战与能力不匹配、反馈不清、失败成本过高 | 是挑战过高，还是目标、规则或反馈不清楚 |
| “我给什么他都只会说同一句话” | 状态响应贫乏、行为缺少后果 | NPC 是否真正读取并更新相关状态，而非只生成不同措辞 |

以上均是诊断假设，不是仅凭一句评论就能确定的心理事实。应结合玩家行为、访谈、原型实验和上下文判断。

## 4. 数字分身应如何执行一次“体验挖掘”

### 输入

一个游戏概念、关卡、NPC 设计、玩家评论集合、试玩记录，或一个用户希望解决的留存 / 体验问题。

### 分析流程

1. **提取观察**：记录玩家原话、具体行为、发生情境与结果，避免先入为主地解释。
2. **标注体验**：区分惊喜、掌控感、好奇、情绪共鸣、挫败、困惑、重复感等。
3. **提出机制假设**：每项假设写明支持信号、反例、置信度与缺失信息。
4. **映射到系统**：指出哪些规则、道具、NPC 状态、任务、叙事线索或反馈可能产生该体验。
5. **寻找交汇点**：主动检查玩法、角色记忆、关系变化和叙事揭示是否可以由同一个玩家行动连接。
6. **识别体验断点**：玩家是否看不懂反馈、失败成本是否过高、NPC 是否前后矛盾、长期目标是否空洞。
7. **提出可验证实验**：设计最小原型、对照条件、成功指标和失败判据。
8. **更新数字分身记忆**：保存已验证的玩家偏好、项目决策、实验结果和反例；不要把推测写成已知事实。

### 标准输出

每次挖掘至少输出：

- **玩家体验目标**：希望玩家感受到什么、在什么时刻感受到。
- **触发结构**：玩家行动 → 系统状态变化 → 可观察反馈 → 体验结果。
- **核心机制假设**：为什么可能奏效。
- **惊喜 / 留存 / 叙事 / 交汇分析**：分别评价，不混为一个总分。
- **风险与反例**：什么情况下不会奏效，哪些玩家可能不喜欢。
- **最小验证方案**：原型范围、需要观察的行为、访谈问题和判定标准。
- **证据状态**：已观察、外部证据支持、设计推断、尚未验证。
- **下一步建议**：先做哪项成本最低、信息价值最高的实验。

## 5. 《越界》（Loophole）作为示例验证域

《越界》的关键假设不是“LLM 能生成很多 NPC 台词”，而是：

**NPC 的状态与世界规则能否让玩家提出未预设的行动组合，并产生可信、可解释、带有后果的结果。**

MVP：一个房间、两个 NPC、五个道具，目标是进入房间。钥匙是明确的正经解法；其他方案由玩家自由组合提出。

NPC 状态至少应包含：

- 欲望 / 当前目标；
- 稳定性格特征；
- 短期状态（情绪、疲劳、饥饿、警觉等）；
- 有来源和时间的记忆；
- 与玩家的关系及其变化；
- 对当前事件的认知；
- 可采取行动的边界与世界规则。

每次行动采用受约束的流程：

玩家行动
→ 解析行动意图与涉及对象
→ 检查世界规则、物品能力和前置条件
→ 由 NPC 状态模型判断可能反应
→ 执行明确的状态变更
→ 生成与状态变更一致的表现 / 对话
→ 记录事件、原因、证据与后果
→ 允许玩家继续尝试或修正理解。

### AI 的职责与边界

- LLM 可用于理解自由文本行动、提出候选结果、生成符合角色的表达。
- 关键状态变更应经过结构化校验；不能仅凭一段流畅的模型回答就宣称行动成功。
- 结果要能追溯到 NPC 状态、记忆、环境条件和规则；出现矛盾时应优先保持世界一致性。
- 不必追求所有组合都成功。失败也应提供有信息量的反馈，让玩家学到规则，而不是被任意拒绝。
- 记录玩家提出的非预设组合、成功 / 失败结果、原因是否可解释，以及玩家是否愿意继续探索。

### MVP 关键指标

- **非预设有效解法率**：有效完成目标的行动中，有多少不是明确提示的标准解法。
- **可解释率**：玩家能否理解结果为何发生。
- **探索持续率**：一次成功或失败后，玩家是否自发尝试其他方法。
- **状态一致性**：NPC 反应是否符合已记录的性格、记忆与当前状态。
- **叙事交汇率**：有多少关键玩法事件同时改变了玩家对 NPC / 世界的理解。
- **挫败来源**：失败来自合理规则、信息不足、模型错误，还是反馈不清。
- **重复体验质量**：相同意图在不同状态下能否产生有依据的差异，而不是随机改写台词。

不要只追求“成功率高”或“结果足够随机”。过高的成功率会让规则失去意义；纯随机会破坏玩家对世界的信任。目标是可探索、可理解、有后果的涌现。

## 6. 与数字分身总体架构的关系

这套框架是 JARVIS 的一个可复用专业能力，而不是只服务《越界》的独立功能。

建议将其纳入游戏概念评估与原型规划工作流：

游戏概念
→ 玩家体验假设
→ 机制 / 叙事交汇地图
→ 风险与证据审查
→ 最小可验证原型
→ 玩家测试
→ 结果分析
→ 数字分身记忆更新
→ 下一轮设计决策。

未来面对 AI 原生 RPG、模拟经营、叙事游戏或其他类型时，数字分身应根据项目调整体验模型，而不是把《越界》的规则生搬硬套到所有游戏。

## 7. 质量门槛

- 不把玩家评价直接等同于心理机制。
- 不把设计假设伪装成研究结论。
- 不把 LLM 生成的反应当作已执行的游戏状态变化。
- 不只给出“有潜力 / 没潜力”，必须说明因果链、反例与验证办法。
- 不只优化留存时长；同时评估玩家自主性、体验质量、挫败和退出体验。
- 每次推荐都说明证据强度与下一步最有信息价值的验证动作。
