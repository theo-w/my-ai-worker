数字分身 ↔ 数字员工：职责与协作边界

设计视图 · 非运行事件

数字分身 / Twin · 目标负责人

决定“下一步做什么”
  • 理解目标、约束与验收标准
  • 优先判断单员工是否足够
  • 分配、合并、取消或重规划任务
  • 处理员工反馈、阻塞与风险
  • 汇总验收结果并向用户汇报
模型可以提出规划或重规划建议；权限、状态、重试上限仍由规则约束。

数字员工 / Worker · 任务执行者

负责“把当前任务做好并反馈”
  • 只领取能力范围内的授权任务
  • 按租约执行并报告进度/心跳
  • 提交结果、来源证据或阻塞原因
  • 根据分身反馈继续、修正或等待
  • 不能自行把结果判定为最终通过
LLM 生成内容只是执行产物；研究证据必须来自实际来源，验收需要独立判断。

规则何时生效

  • 目标进入时：输入、权限与风险检查
  • 派发时：能力、状态、租约和依赖检查
  • 执行中：事件权限、心跳与超时规则
  • 验收时：证据要求、审批和状态转换
  • 失败时：重试预算和终止条件

LLM 何时生效

  • 规划：拆解目标、提出任务组合
  • 执行：生成研究分析、代码或其他产物
  • 反馈后：解释阻塞并建议下一步
  • 调研：只有有效来源通过门槛后才可辅助综合
  • 验收：只有明确配置独立审查器时才参与，不能自批
重要现状：持久化员工任务 API 与自主规划/执行路径仍未完全统一。此卡片说明职责和规则边界，不代表每个 Twin 决策都已被运行时记录。真实决策轨迹接通后，应在下方事件时间线中区分 Twin 决策、员工动作、规则判定和 LLM 调用。
